# Design

## Context

工具集新增「Cron 表达式解析」。核心难点有二：① 未来执行时间计算（月长、闰年、日/周 OR 语义），易错，交给成熟库；② 中文描述与逐段报错，无现成库满足（cron-parser 报错为英文且不含段定位），自实现字段解析器。全部计算在浏览器本地同步完成，无网络请求。已用 cron-parser@5.10.2 实测确认关键行为（见下）。

## Decisions

### 库选型论证

| 方案                    | 结论     | 理由                                                                                                                                                                                                                                |
| ----------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **cron-parser（v5）**   | **采用** | 未来执行时间计算事实标准：原生支持 5/6 段（6 段自动含秒）、月/周英文名、`?`、宏（@daily 等）、日/周标准 OR 语义；自带 TypeScript 类型（v5 起 ESM 双发，Vite 直引）；API `CronExpressionParser.parse(expr).take(n)` 直接产出迭代序列 |
| 自实现下次执行时间      | 弃用     | 需正确处理月长/闰年/日周 OR 语义/字段联动（如「2 月 31 号」永不触发），正确实现 200+ 行且边界全靠实测，收益为零                                                                                                                     |
| cronstrue（描述生成）   | 弃用     | 有 i18n 中文，但描述粒度与本工具「字段分解表」重复，且对 6 段/方言边界控制不如自解析；描述生成逻辑针对 5 段常见模式自实现约 100 行，可控可测                                                                                        |
| 自实现字段解析（utils） | **采用** | 逐段取值集合展开（分解表「取值集合」列）与逐段中文报错（指明第几段、为何错）均无现成库；语法仅 `*` `/` `-` `,` 四类，实现 ~120 行                                                                                                   |

实测（cron-parser@5.10.2）：5 段/6 段/英文名/宏/`?`/`L`（月末）/`6#3`（第 N 个周 X）均可解析，`15W` 报错，@reboot 报错；错误为英文（`Constraint error, got value 60 expected range 0-59`），不含段序号——故校验层自实现、cron-parser 仅用于已验证合法表达式的执行时间计算。

### 方言边界（显式决策）

- **支持**：标准 5 段（分 时 日 月 周）；6 段带秒（段数 = 6 时自动识别，首段为秒 0-59）；月/周英文名（JAN-DEC、SUN-SAT，大小写不敏感）；周日可用 `0` 或 `7`；`?`（视同 `*`，仅限日/周两段，其他段报错）；宏 `@yearly`/`@annually`/`@monthly`/`@weekly`/`@daily`/`@midnight`/`@hourly`（展开为标准 5 段后走同一管线）
- **拒绝并提示**：Quartz 扩展 `L` / `W` / `#`（报「第 N 段：Quartz 扩展语法 'X' 暂不支持」）——cron-parser 虽部分支持（L、#），但描述与分解表需同步实现其语义，部分支持比明确拒绝更误导，故统一拒绝；`@reboot`（无法用时间表达）；7 段带年（段数报错中提示仅支持 5/6 段）
- **语义**：日/周同时限制时按标准 cron OR 语义（cron-parser 默认行为），UI 不额外解释，描述文案如实反映两字段

### 校验与报错管线（utils.ts）

输入 trim → 宏展开（含 @reboot 拒绝）→ 按空白分段 → 段数校验（5 或 6，否则报「需要 5 段（分 时 日 月 周）或 6 段（带秒），当前 N 段」）→ 逐段 `parseField`：

- 语法：`*`、`a-b`、`a-b/n`、`*/n`、`a/n`（= a-max/n）、`,` 列表组合；名字先映射为数值再校验
- 段定义（带范围/别名/中文名）：秒 0-59、分 0-59、时 0-23、日 1-31、月 1-12（JAN-DEC）、周 0-7（SUN-SAT，7 归一为 0）
- 报错文案统一格式「第 N 段「段名」：原因」，原因覆盖：取值超界（取值 X 超出 min-max）、无法解析（'abc'）、步长为 0 或超界、区间倒置（a-b 需 a ≤ b）、Quartz 扩展（L/W/#）、`?` 用在非日/周段
- 首个错误即返回（避免级联噪音）

### 结果派生（合法输入）

- **字段分解**：每段输出 `{段名, 原始值, 含义, 取值集合}`；取值集合压缩展示——全集显示「全部（min-max）」、等差步进显示「a, a+k, …（共 N 个）」、其余连续段合并为区间（如 `9-17, 20`），过长截断
- **中文描述**：模式匹配优先（每分钟/每 n 分钟/每小时第 m 分/每天 HH:mm/每周 X…/每月 N 号/每年 M 月），命中常见组合输出自然短句（如「工作日（周一至周五）9:30」）；未命中时按段组合兜底（「于 <月描述> <日描述> <周描述> <时分描述>」），保证任意合法表达式都有输出
- **未来 N 次执行**：`CronExpressionParser.parse(expr).take(n)`（n ∈ 5/10/20，UI Segmented），本地时区格式化为 `YYYY-MM-DD HH:mm:ss 星期X`（自实现格式化，不引日期库）

### UI 结构

输入卡（mono Input + 复制按钮 + 速查 Tag 行）→ 非法时错误 Alert（工具色描边）→ 合法时三卡：描述卡（工具色标题点缀）、未来执行时间卡（Segmented 切条数 + 序号列表 + 「按本地时区（GMT±X）计算」说明）、字段分解卡（antd Table 四列）。全部 useMemo 派生，输入即解析，无提交按钮。

## Risks / Trade-offs

- 描述生成不可能覆盖所有组合的「自然语言级」优雅度 → 兜底组合式描述保证正确性优先
- 拒绝 L/W/# 与 crontab 用户的 Quartz 习惯冲突 → 报错文案明示「暂不支持」及替代写法提示（L → 每月最后一天无标准等价，如实说明）
