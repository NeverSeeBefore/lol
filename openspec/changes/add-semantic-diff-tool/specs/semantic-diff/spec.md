# Spec Delta

## Purpose

定义「文本/JSON 语义 Diff」工具能力：双栏输入（左旧右新）+ 下方 Diff 结果视图，Segmented 切换文本行级 diff 与 JSON 语义 diff 两种模式。文本模式基于 jsdiff（Myers）行级比对，相邻删+增块按行配对为「修改」；JSON 模式键序无关递归比对，按路径展示变更（如 `a.b[2].c: old → new`），值类型变化单独标注。非法 JSON 给出面板侧与行列定位的友好报错。统计条报告增/删/改数量。大输入超阈值时降级为手动触发。全程浏览器本地完成，无网络请求。

## ADDED Requirements

### Requirement: 双模式与输入

系统 SHALL 提供「文本」「JSON」两种对比模式，以 Segmented 控件切换。系统 MUST 提供左右两个输入面板（左为旧版本、右为新版本）。未超性能阈值时，输入变更或模式切换 MUST 立即重新对比（派生计算，无需点击按钮）。两侧均为空时 MUST 不显示错误、结果区显示空态。

#### Scenario: 输入即对比

- **WHEN** 两侧输入均在性能阈值内且任一输入变化
- **THEN** 结果视图立即刷新为最新 diff，无需手动触发

#### Scenario: 空输入

- **WHEN** 左右两侧均为空
- **THEN** 不显示任何错误，统计为零

#### Scenario: 模式切换

- **WHEN** 用户在文本与 JSON 模式间切换
- **THEN** 两侧输入内容保留，结果按新模式重新计算

### Requirement: 文本行级 Diff

文本模式下系统 MUST 以行为单位比对两侧文本，结果视图 MUST 渲染行号与 +/-/~ 标记，并按类型着色：新增行绿色（--success 系）、删除行红色（--error 系）、修改行琥珀色（--accent-text 系），未变更行不着色。相邻的删除块与新增块 MUST 按行配对为「修改」（取两边行数较小者配对，剩余行归为纯新增或纯删除）。统计条 MUST 显示 `+N 行 / -N 行 / 修改 M 处`。系统 MUST 在比对前将 CRLF/CR 统一归一化为 LF、并对末尾缺失换行的一侧按补齐处理——行尾风格差异 MUST NOT 产生幻影修改。

#### Scenario: 纯新增

- **WHEN** 新文本比旧文本多出 2 行
- **THEN** 结果中该 2 行标记为新增（绿色），统计显示 `+2 行`

#### Scenario: 末尾无换行的纯新增

- **WHEN** 旧文本为 `a`（末尾无换行），新文本为 `a\nb\nc`
- **THEN** 统计显示 `+2 行 / 修改 0 处`，公共行 `a` MUST NOT 被配成幻影修改

#### Scenario: CRLF 与 LF 行尾混用

- **WHEN** 旧文本为 `a\r\nb`，新文本为 `a\nb`（仅行尾风格不同）
- **THEN** 统计显示零变更，无幻影修改

#### Scenario: 末尾附近的修改与新增

- **WHEN** 旧文本为 `alpha\nbeta\ngamma`（末尾无换行），新文本为 `alpha\nBETA\ngamma\ndelta`
- **THEN** 统计显示 `修改 1 处 / +1 行`，公共行 `gamma` 不计入修改

#### Scenario: 纯删除

- **WHEN** 新文本比旧文本少 1 行
- **THEN** 结果中该行标记为删除（红色），统计显示 `-1 行`

#### Scenario: 修改配对

- **WHEN** 旧文本某行在新文本中被替换为另一行（删块与增块相邻且可配对）
- **THEN** 该对行标记为修改（琥珀色），统计显示 `修改 1 处`，不计入增删行数

#### Scenario: 增删混合

- **WHEN** 文本同时包含新增、删除与修改
- **THEN** 三类各自正确着色与计数

### Requirement: JSON 语义 Diff

JSON 模式下系统 MUST 先解析两侧 JSON，再做键序无关的递归比对，以变更列表展示结果。每条变更 MUST 包含：JSON 路径（对象键用 `.` 连接，数组下标用 `[n]`，如 `a.b[2].c`）、变更类型（新增/删除/修改）、相关值。值类型发生变化（如 string → number、对象 → 数组）时 MUST 在条目上标注「类型变化」。键顺序不同但内容相同的两个 JSON MUST 产出零变更。统计条 MUST 显示 `+N 键 / -N 键 / 修改 M 处`。

#### Scenario: 键序无关

- **WHEN** 两侧 JSON 内容相同仅键顺序不同
- **THEN** 结果显示无变更，统计为零

#### Scenario: 嵌套路径变更

- **WHEN** 新 JSON 中 `a.b[2].c` 的值从 `1` 变为 `2`
- **THEN** 变更列表含路径 `a.b[2].c`，展示 `1 → 2`，统计 `修改 1 处`

#### Scenario: 类型变化标注

- **WHEN** 某键的值从字符串变为数字，或从对象变为数组
- **THEN** 该条目标注「类型变化」

#### Scenario: 键的新增与删除

- **WHEN** 新 JSON 新增键 `x.y`、删除键 `x.z`
- **THEN** 变更列表分别标记新增与删除，统计 `+1 键 / -1 键`

### Requirement: JSON 解析错误定位

JSON 模式下任一输入解析失败时，系统 MUST 给出友好错误提示，指明出错的侧面板（左/右）；错误消息含位置信息时 SHOULD 给出完整行列（形如「左侧 第 3 行第 5 列：原因」，V8 自带 `(line N column M)` 优先，`at position N` 自行换算次之）；词法级错误无位置信息时 MUST 如实降级为原始原因，不得编造行列。一侧出错时结果区 MUST NOT 展示基于残缺数据的 diff。

#### Scenario: 左侧非法 JSON

- **WHEN** 左侧输入为非法 JSON
- **THEN** 错误提示以「左侧」开头并含行列定位（可定位时）

#### Scenario: 右侧非法 JSON

- **WHEN** 右侧输入为非法 JSON
- **THEN** 错误提示以「右侧」开头并含行列定位（可定位时）

### Requirement: 大输入性能边界

系统 MUST 定义并执行性能阈值：两侧合计行数或字符数超阈值时 MUST 停止实时对比，降级为手动触发（「对比」按钮），并在界面提示当前处于手动模式。Diff 结果渲染 MUST 设行数上限，超限截断并提示截断数量。单侧 1 万行文本的对比 MUST 在可接受时间内完成（不卡死页面）。

#### Scenario: 超阈值降级

- **WHEN** 两侧合计输入超过性能阈值
- **THEN** 实时对比关闭，界面提示需点击「对比」按钮手动触发；点击后正常产出结果

#### Scenario: 万行文本

- **WHEN** 输入 1 万行文本进行对比
- **THEN** 页面保持可交互，diff 结果正常渲染（超限部分截断并提示）
